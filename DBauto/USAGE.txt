  drop_hidden_products.py         ★데이터 전처리★  엑셀에서 display=no 인 제품을

================================================================================
 A.  데이터 전처리 도구 :  drop_hidden_products.py
================================================================================

무엇을 하나
  1) 기준 시트(product_spec_basics)에서 display 값이  no / n / false / 0  인 행의
     model_code 를 모은다.
  2) 워크북의 "모든 시트"에서 그 model_code 에 해당하는 행을 삭제한다.
  3) 값·헤더는 그대로 둔 새 파일로 저장한다.
     (셀 서식·수식·열너비 등 스타일은 보존되지 않음 — DB 덤프 전처리용)
  ※ 20만 행급 시트도 처리 가능하도록 read-only 스트리밍 → write-only 재작성 방식.

기본 실행
      python drop_hidden_products.py structured-us.xlsx
        → structured-us.filtered.xlsx  생성 (원본은 그대로)

옵션
      -o, --output PATH     결과 저장 경로 지정
      --in-place            원본에 덮어쓰기. 원본은  <이름>.bak.xlsx  로 자동 백업
      --dry-run             저장하지 않고 "시트별 몇 행이 지워질지" 표만 출력
      --basics-sheet NAME   기준 시트명            (기본: product_spec_basics)
      --display-col  NAME   display 컬럼명         (기본: display)
      --model-col    NAME   model_code 컬럼명      (기본: model_code)
      --extra-model-cols A,B
                           model_code 와 동일 취급할 추가 컬럼명 (콤마 구분)
                           기본: buying_model_code,representative_model
                           - product_order  시트는 model_code 컬럼이 없어
                             representative_model 로 매칭
                           - product_trade_in 시트는 buying_model_code 로 매칭
                           끄려면:  --extra-model-cols ""

사용 예
      # 먼저 얼마나 지워지는지 확인
      python drop_hidden_products.py structured-us.xlsx --dry-run

      # 결과 파일명 지정
      python drop_hidden_products.py structured-us.xlsx -o clean.xlsx

      # 원본 자체를 정리 (clean.bak.xlsx 백업 생김)
      python drop_hidden_products.py structured-us.xlsx --in-place

      # display 컬럼명이 다른 워크북
      python drop_hidden_products.py other.xlsx --display-col is_display --model-col code

출력 예 (--dry-run)
      sheet                      model_cols            before  deleted   after
      sr_merged_product          model_code              2943      580    2363
      product_order              representative_model   19208     3122   16086
      product_spec_spec          model_code            207466    48444  159022
      ...
      TOTAL                                            273120    58437  214683

참고
  - model_code 매칭 컬럼이 하나도 없는 시트는 "(none - skipped)" 로 건너뜀.
  - product_cstrt_info 처럼 model_code 값이 번들 ID 인 시트는 자연히 0건.
  - 종료 코드 0 = 정상. 숨김 대상이 0개면 파일을 만들지 않고 종료.

 B-1.  스모크 테스트 :  scope_test.py
────────────────────────────────────────────────────────────────────────────────
목적:  각 카테고리에서 제품 1개씩만 뽑아 "카테고리별로 스크랩이 되긴 하는지" 확인.

      SAMSUNG_MENU="TV & Audio" python scope_test.py

결과:  stderr 진행 로그 / stdout 요약 표 / scope_test_result.json (전체 레코드)

────────────────────────────────────────────────────────────────────────────────
 B-2.  원스톱 전체 검증 :  run_scope_test.py     ← 보통 이걸 쓴다
────────────────────────────────────────────────────────────────────────────────
실데이터 xlsx 하나만 주면:
   1) 실데이터 로드
   2) GNB 모든 L0 메뉴의 PF 페이지를 canonical URL 로 dedup 해 순회 스크랩
      → scrape_YYYYMMDDHHmm.json  (+ .dedup.json)
   3) (sku, sort_type) 로 제품 레벨 dedup 후 실데이터와 필드별 PASS/FAIL
   4) result_YYYYMMDDHHmm.xlsx  리포트 저장

기본 실행 (전 메뉴·전 PF·전 조합 — 정확하지만 오래 걸림, 수십 분~수 시간)
      python run_scope_test.py structured-us.xlsx

다른 사이트 (samsung.com/ca, /ca_fr)
      python run_scope_test.py structured-ca.xlsx    --site ca    --fresh
      python run_scope_test.py structured-ca-fr.xlsx --site ca_fr --fresh
      → 결과/캐시가 사이트별로 분리됨:
        scrape_<site>_*.json / result_<site>_*.xlsx / pf_cache_<site>/ / progress_<site>.json
      ※ ca_fr 은 GNB 메뉴/정렬 라벨이 프랑스어지만 sort code·URL 슬러그는 영어라
        --menu/--categories 없이(전체) 돌리는 걸 권장. 필요하면 프랑스어 이름을 넣는다.

자주 쓰는 형태
      # 카드의 기본(대표) 조합 1개만 → 훨씬 빠름
      python run_scope_test.py structured-us.xlsx --default-only

      # 실데이터에 등장하는 카테고리만 스캔
      python run_scope_test.py structured-us.xlsx --from-data

      # 특정 메뉴/카테고리만
      python run_scope_test.py structured-us.xlsx --menu Mobile
      python run_scope_test.py structured-us.xlsx --categories "Galaxy Watch,Galaxy Tab"

      # 이미 만든 스크랩 JSON 재사용 (재스크랩 생략, 대조만 다시)
      python run_scope_test.py structured-us.xlsx --scrape-json scrape_202609092208.json

      # 중단됐다가 이어하기 (PF 단위 체크포인트가 <outdir>/pf_cache 에 쌓임)
      python run_scope_test.py structured-us.xlsx          # 그냥 다시 실행하면 이어서
      python run_scope_test.py structured-us.xlsx --fresh  # 캐시 비우고 처음부터

옵션
      --default-only        카드의 기본(대표) 조합 1개만 수집
      --max-cards N         PF 당 상위 N개 카드만
      --menu NAME           L0 메뉴 1개만            (기본: 전체 L0 메뉴)
      --menus "A,B"         L0 메뉴 여러 개 (쉼표구분)
      --categories LIST     L1 카테고리 이름 필터 (쉼표구분)
      --from-data           실데이터의 product_url/카테고리에 등장하는 것만
      --scrape-json PATH    기존 스크랩 JSON 재사용
      --verify-sku-sample N PF 마다 첫 N개 variant 는 Quick View 로 SKU 교차검증
      --resume DIR          PF 체크포인트 폴더 (기본 <outdir>/pf_cache)
      --fresh               체크포인트 폴더를 비우고 처음부터
      --progress-file P     진행 상황 JSON 경로 (기본 <outdir>/progress.json)
      --outdir DIR          결과 저장 폴더 (기본: 현재 폴더)

result_YYYYMMDDHHmm.xlsx 시트 구성
      Summary      메타 + 집계 (PASS / FAIL / FAIL*(volatile) / SKIP / NOT_FOUND)
      Detail       model_code × field 별 전체 판정
      Failures     result=FAIL 만
      NotFound     실데이터엔 있는데 스크랩에서 매칭 안 된 model_code
      Ambiguities  같은 (sku, sort_type)인데 PF에 따라 값이 다른 항목
      SkuAudit     DOM SKU ↔ Quick View SKU 교차검증 불일치 (--verify-sku-sample 시)

종료 코드:  strict FAIL 이 1건이라도 있으면 1, 없으면 0

────────────────────────────────────────────────────────────────────────────────
 B-3.  스크래퍼 단독 :  verify_samsung_smartphones.py
────────────────────────────────────────────────────────────────────────────────
CLI 인자는 없다. 모든 조정은 환경변수로 한다.

      python verify_samsung_smartphones.py > scrape.json 2> scrape.log

표준출력(stdout):  JSON 객체
      {
        "records": [ { ...레코드... }, ... ],
        "count_verification": [ { PF별 SKU 개수 검증 결과 }, ... ]
      }
표준에러(stderr):  진행 로그 + [verify] 요약 라인

레코드 주요 필드
      category, source_pf_url, source_menus
      sort_type("Recommended"|"Newest"), sorting_no, is_default
      model_code / sku, model_name, display_name, product_color, capacity
      standard_price, final_price, currency, on_sale, discount_amount,
      monthly_price, monthly_months
      badge, image_url, rep_image_url, product_url, cta_pd_url, family_id
      review_count, review_rating_score
      stock_level_status, sku_source("dom"|"dom-stable"|"quickview"...),
      sku_audit_mismatch(있을 때만)

가격 규칙
      standard_price = 카드의 정가(price-ux__price-save-was, 없으면 현재가)
      카드에 "Save $X" 표기가 있으면
          final_price = standard_price − max(Save $X)        (최대 할인 적용)
          on_sale = true,  discount_amount = max(Save $X)
      표기가 없으면
          final_price = standard_price

개수 검증 (count_verification)
      PF(canonical path) × sort_type 별 "고유 SKU 수"를 EXPECTED_COUNTS 와 대조.
        Recommended : actual == expected                       → pass
        Newest      : expected ≤ actual ≤ expected + N          → pass
                      (N = SAMSUNG_NEWEST_TOLERANCE, 기본 1.
                       추출 시점 이후 신제품이 1개까지 늘 수 있어 허용)
      기대치는 파일 상단 EXPECTED_COUNTS 딕셔너리(비어 있음)에 직접 채우거나
      SAMSUNG_EXPECTED_COUNTS 환경변수로 JSON 주입:
        SAMSUNG_EXPECTED_COUNTS='{"/us/watches/all-watches": 30}'
      MAX_CARDS / MAX_COMBOS / DEFAULT_ONLY 중 하나라도 켜지면 부분 스캔이므로
      판정 없이 counts 만 보고("skipped: partial scan").

환경변수 레퍼런스
      SAMSUNG_SITE             대상 사이트: us | ca | ca_fr (기본 us). BASE_URL·통화 결정
      SAMSUNG_MENUS            스캔할 L0 메뉴들 (쉼표구분). 미설정 = GNB 전체 메뉴
      SAMSUNG_MENU            (하위호환) 단일 메뉴 이름. 기본 "Mobile"
      SAMSUNG_CATEGORIES      L1 카테고리 이름 필터 (예 "Galaxy Watch,Galaxy Tab")
      SAMSUNG_MAX_CARDS       PF 당 상위 N개 카드만. 0/미설정 = 전체
      SAMSUNG_MAX_COMBOS      카드당 색상×용량 조합 상한. 0/미설정 = 전체
      SAMSUNG_DEFAULT_ONLY    1 이면 카드의 기본(대표) 조합 1개만
      SAMSUNG_RESUME_DIR      PF 단위 체크포인트 폴더. 지정 시 저장·재사용
      SAMSUNG_EXPECTED_COUNTS 개수 검증 기대치 JSON (canonical path → int)
      SAMSUNG_NEWEST_TOLERANCE  Newest 개수 허용 오차 (기본 1)
      SAMSUNG_QV_AUDIT_N      PF 마다 첫 N개 variant Quick View SKU 교차검증

예시
      # Mobile 메뉴만, Watch·Tab 카테고리만
      SAMSUNG_MENUS="Mobile" SAMSUNG_CATEGORIES="Galaxy Watch,Galaxy Tab" \
        python verify_samsung_smartphones.py > scrape.json 2> scrape.log

      # 빠른 확인 (제품 1개, 조합 3개까지)
      SAMSUNG_MAX_CARDS=1 SAMSUNG_MAX_COMBOS=3 python verify_samsung_smartphones.py

      # 개수 검증까지
      SAMSUNG_EXPECTED_COUNTS='{"/us/audio-sound/all-audio-sound": 7}' \
        SAMSUNG_CATEGORIES="Galaxy Buds" python verify_samsung_smartphones.py

────────────────────────────────────────────────────────────────────────────────
 B-4.  대조 단독 :  verify.py
────────────────────────────────────────────────────────────────────────────────
스크랩 결과 JSON 과 실데이터 xlsx 를 받아 필드별 PASS/FAIL 만 다시 계산.

      python verify.py <scraped.json> <expected.xlsx>
        → 표 출력 + verify_result.json  (종료 코드: strict FAIL 있으면 1)

  ※ 여기서 <scraped.json> 은 "레코드 배열" JSON 이어야 한다.
     - run_scope_test.py 가 만든  scrape_YYYYMMDDHHmm.json  을 그대로 넣으면 됨.
     - verify_samsung_smartphones.py 를 직접 돌린 출력은 {"records":[...], ...}
       형태이므로 records 만 꺼내서 넣는다:
         python -c "import json,sys; json.dump(json.load(open(sys.argv[1]))['records'], open(sys.argv[2],'w'))" out.json recs.json
         python verify.py recs.json structured-us.xlsx

판정 규칙
      EXACT   값이 정확히 일치해야 PASS
      TOL     ±10%(TOLERANCE_RATIO) 이내면 PASS
              → review_count, review_rating_score (추출/검증 시점 차이 보정)
      volatile 필드(final_price, on_sale, stock_level_status, sorting_no)는
              시점에 따라 정상적으로도 바뀌므로 FAIL 시 "FAIL*" 로 분리 집계.
      실데이터에 기대값이 없으면 SKIP, 스크랩에 값이 없으면 FAIL.

================================================================================
 D.  다중 사이트  (samsung.com/us · /ca · /ca_fr)
================================================================================
같은 파이프라인을 미국(us) / 캐나다 영어(ca) / 캐나다 프랑스어(ca_fr) 에 쓴다.
사이트는 URL 경로 프리픽스 그대로다: https://www.samsung.com/<site>/

실행
      python run_scope_test.py structured-us.xlsx    --site us    --fresh
      python run_scope_test.py structured-ca.xlsx    --site ca    --fresh
      python run_scope_test.py structured-ca-fr.xlsx --site ca_fr --fresh

  스크래퍼 단독으로 돌릴 땐 환경변수:
      SAMSUNG_SITE=ca    python verify_samsung_smartphones.py > scrape.json
      SAMSUNG_SITE=ca_fr python verify_samsung_smartphones.py > scrape.json

사이트별로 분리 저장되는 것 (서로 안 덮어씀)
      scrape_<site>_YYYYMMDDHHmm.json  /  .dedup.json
      result_<site>_YYYYMMDDHHmm.xlsx
      pf_cache_<site>/                 (이어하기 체크포인트)
      progress_<site>.json

자동으로 흡수하는 us↔ca 차이 (별도 설정 불필요)
      - URL 프리픽스(/us/ → /ca/ → /ca_fr/) 와 통화(USD → CAD)
      - 정렬: CA 는 정렬 옵션이 label 이 아니라 radio(input#newest) 라서
        코드(newest/recommended)로 클릭. ca_fr 는 정렬/메뉴 라벨이 프랑스어
        ("Les plus récents" 등)라도 sort_type 은 항상 "Recommended"/"Newest" 로 기록
      - 가격 표기: us "From $1,799.99 or $75/mo", ca "Total Price: From $39.58/mo
        ... or $949.99"(월납 선행), ca_fr "Prix total: 949,99 $"(콤마 소수점·접미 $)
        → 모두 실제 최종가로 파싱. "Save $X"/"Économisez X $"/"-X $" 도 처리
      - CA 카드 마크업: Buy 링크가 a.js-pfv2-buy-now(href=javascript:;, 경로는
        data-config_info), 색상칩에 data-chip-value 없음(an-la="color:..." 에서 추출)
      - 메뉴 라벨의 NEW / NOUVEAU / NOUVEAUTÉ 꼬리표 제거
      - 불어(é 등) 콘솔 출력 인코딩

메뉴/카테고리 필터 주의 (ca_fr)
      GNB L0 메뉴명이 프랑스어다(Mobilité, Appareils connectés, Électroménager…).
      --menu / --menus / SAMSUNG_MENUS 는 표시 라벨과 정확히 일치해야 하므로
      ca_fr 에선 필터 없이(전체) 돌리는 걸 권장.
      --categories / SAMSUNG_CATEGORIES 도 프랑스어 L1 이름을 넣어야 한다.
      URL 슬러그(smartphones, watches, tablets …)는 세 사이트 모두 영어라
      --from-data(실데이터 기반 카테고리 추출)와 sorting_no 비교 게이팅은 그대로 동작.

img_url (CA / CA_FR)
      PF 카드는 썸네일 URL(-thumb-<id>...$Q90_330...)만, DB 는 원본
      (-<id>...$PD_GALLERY_PNG$). verify.norm() 이 '-thumb-' 마커와 끝 자산 id 를
      떼고 .../gallery/<slug>-<modelcode> 안정부만 비교 -> 99% 일치. PDP 방문 불필요.

가격 정밀 보강 (shop_price.py, 전 사이트 자동)
      PF 카드는 현재가(프로모가)만 보여줘 standard_price 가 자주 어긋난다.
      run_scope_test.py 가 스크랩 직후 Samsung 커머스 API 를 호출해 교체한다:
        GET api.shop.samsung.com/tokocommercewebservices/v2/<site>/products/<code>
        -> price.value(정가) / promotionPrice.value(할인가) / currencyIso
      병렬 HTTP, ~2KB/건, 사이트당 1~2분. 원본은 *_pf 로 보존,
      PF 현재가와 API 최종가 차이(>2%)는 price_drift_pf_vs_api 로 표시.
      끄기: run_scope_test.py ... --no-price-api
      단독: python shop_price.py scrape_ca_XXXX.json --site ca
      (on_sale 은 안 건드림 - DB on_sale 은 '할인'이 아니라 '오퍼 존재' 의미)

알려진 한계
      CA 카드는 data-feedback-param 이 비어 있어 display_category_major /
      display_category_middle 를 카드에서 못 읽는다 → 이 두 필드는 volatile 로
      분류돼 strict FAIL 로 집계되지 않는다. (핵심 필드 SKU/가격/이름/정렬은 정상)

================================================================================
 F.  자주 겪는 문제
================================================================================
  - 스크랩이 0건 / 카테고리가 계속 skip
      → 제품 파인더가 화면에 들어와야 카드를 렌더한다(lazy-load). 네트워크가
        느리면 wait_for_pf 폴링(~30초) 안에 안 뜰 수 있음. 재실행하면 pf_cache
        덕에 성공한 PF 는 건너뛴다.

  - 카드 많은 PF(액세서리 등)에서 제품 일부만 잡힘 / NOT_FOUND 대량
      → PF 그리드는 무한 스크롤이라 첫 배치(~20개)만 렌더된다. extract_all 이
        정렬마다 load_all_cards() 로 상단 "N Results" 수 또는 증가가 멈출 때까지
        끝으로 스크롤해 전부 로드한다(액세서리 PF 하나당 +30~60초).
        stderr 에 "[warn] load_all_cards: n/target 만 로드됨" 이 뜨면 그 PF 는
        스크롤이 target 에 못 미친 것 → 재실행하거나 max_iter 를 늘린다.

  - "Element is outside of the viewport" 류로 조합 일부 실패
      → 스와이퍼 캐러셀에 가린 칩. JS 클릭으로 폴백하지만 그래도 실패하면 해당
        레코드에 error 필드가 남고 나머지는 계속 진행된다.

  - 쿠키 배너(TrustArc)가 클릭을 가로챔
      → dismiss_consent() 가 제거·차단하지만, 매우 느린 회선에서 배너가 뒤늦게
        다시 뜨면 정렬 전환이 한 번 실패할 수 있음. 재실행 권장.

  - drop_hidden_products.py 가 특정 시트에서 아무 것도 못 지움
      → 그 시트의 model_code 컬럼명이 다른 것. --model-col / --extra-model-cols
        로 지정. --dry-run 의 model_cols 열에서 어떤 컬럼을 썼는지 확인.

  - 전체 실행이 너무 오래 걸림
      → run_scope_test.py --default-only 로 대표 조합만, 또는 --from-data /
        --categories 로 범위를 좁힌다. 중단해도 pf_cache 로 이어진다.

  - ca / ca_fr 인데 "unique PF pages=0"
      → --site 를 안 줬거나(기본 us) 잘못 줬다. --site ca / --site ca_fr 확인.
        ca_fr 에서 --menu/--categories 를 영어로 줬으면 매칭 실패 → 빼고 전체 실행.

  - ca_fr 실행 시 UnicodeEncodeError (é 등)
      → 스크립트가 stdout 을 UTF-8 로 재설정하므로 최신 버전에선 안 난다.
        직접 파이프로 받을 땐 PYTHONUTF8=1 를 붙이면 확실하다.
